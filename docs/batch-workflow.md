# 批次处理、保存和复核

当前仓库为用户指定的**公开 GitHub 仓库**。每1000道已逐题处理的题保存一批，明确区分作答内容完整性、解析核验意见和模型审核状态。完成批次不等于每道题都没有争议，也不等于用户亲自批准了每个词条。

1. 原始签名题库不移动、不重写、不重签。所有补充按 bankId、questionId、releaseId、manifestHash、revisionDigest 精确关联。旧七题样例保留，新批次可以通过显式顺序覆盖其读取版本。
2. 每题保存重点解析与秒杀技巧。没有可靠捷径时说明常规检查步骤，不编造结论或支持原答案的理由。记录读取原题、选项、材料、图片与计算核验的依据。
3. **完整题以原始答案判分。** 答案与解析存在矛盾时客观注明，不因此把完整题归为缺失或自动改成自评。模型 pending 也不影响原题判分。
4. 缺题干、选项或必需材料/图像时，先检查同卷题组，再查可靠外部来源；逐项比对题目身份、数值单位和选项，不从原答案反推材料。可靠恢复通过受控材料侧车展示。只有摘要而仍缺原文时保留部分恢复标记。
5. 无法完全恢复的题放在 `missing-content/<batch>/`，保存题目ID、修订摘要、缺失说明及检索证据引用，不移动原始签名路径。已找到但题型/占位答案仍无法安全恢复的候选也在这里解释。
6. 模型索引只引用实际字典版本中的代码。经实质核验可标为AI审核，未核实、准确词条缺口或隔离状态照实保留。不同字典版本分子批保存，不把定义审核等同于每题映射审核。
7. 发布前验证原文件摘要及签名、记录唯一性与修订绑定、材料和模型合同、网页消费投影、测试结果、敏感信息和文件体积。失败或未运行的项目明确写入批次报告。
8. 使用用户已授权的 GitHub 身份核实远端精确为 `https://github.com/hky685021-star/kymind-aptitude-bank.git` 且公开。先 fetch 检查远端更新，正常合并，不强推覆盖其他提交。推送后比较远端main与本地提交摘要。
9. 私有恢复备份与公开发布分开：工作中的候选和检查点标记未发布，不能当成已公开完成。正式发布清单在 `provenance/batches/<batch>/`。

网页只读取已保存资料，不自动请求模型。此仓库未连接正在运行的本机应用数据库；静态文件兼容既有补充结构不等于已通过本机受控接口导入。后续实质修订需保留版本和证据，不悄悄覆盖已发布历史。
