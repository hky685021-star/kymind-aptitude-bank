# 后续批次保存与同步

用户已要求：后续每完成一批题库修改，就同步到这个私有 GitHub 仓库。此授权覆盖已完成的相关批次提交，不表示自动批准答案、模型候选或全库批量继续。

1. 在本仓库建立新的日期/批次目录，不覆盖既有批次。AI 补充放在 `supplements/ai/batches/`，未批准模型索引放在 `candidates/model-index/`。
2. 绑定原始 `bankId`、`questionId`、`releaseId`、`manifestHash`、`revisionDigest`。保存来源、修改说明和明确审核状态。缺图、缺材料和冲突保持阻断。
3. 完成本批所需核对和测试，记录通过、失败、未运行项；不得用“已提交”代替“已审核”。未经批准的模型候选仍保留 `pending`。
4. 提交前运行本仓库校验，检查新文件敏感信息、大文件、实际差异及工作区。原始签名文件不得静默修改；若未来需要正式新发行，另行走题库发行流程。
5. 再确认 `origin` 是 `https://github.com/hky685021-star/kymind-aptitude-bank.git`，GitHub 仍为 private，检查远端更新。若他人已提交，先读取和合并，不强推覆盖。
6. 每批一个清楚的提交说明，推送后比较远端 `main` 与本地提交 SHA，报告本批范围和剩余问题。

没有配置定时器、GitHub Actions 或“任何本地文件一变就上传”的监控。同步发生在明确批次完成时；当前首批只是原题归档和既有七题待审材料备份。
